Architecture & System Design

A technical overview of runtime architecture, local storage, and network behavior in MySoundLib.

Architecture & Subsystems

MySoundLib is distributed as a standalone desktop binary. It runs directly on your operating system without web runtimes, browser engines, or background servers.

Subsystem Technical Scope
Windowing & Overlay Engine Native OS windowing, global shortcut daemon, low-latency QuickSearch overlay, and system drag-and-drop protocols.
Audio Decoding Engine Low-latency PCM stream decoding, sample-accurate waveform extraction, and fast buffer downsampling.
Format Transcoding Core Audio container validation, multi-format transcoding (WAV, MP3, FLAC, OGG, M4A), and broadcast metadata parsing.
Embedded Database Zero-configuration, serverless local database for sub-millisecond audio indexing and keyword search.

Storage & Data Isolation

  • Data Locations: Database records (*.db), configuration (config/), and diagnostic logs (debug/) reside in Documents/MySoundLib by default on Windows (customizable in Settings), with the application binary installed in per-user AppData (%LOCALAPPDATA%/Programs/MySoundLib).
  • Non-Destructive Indexing: Audio folders are scanned in read-only mode. Source files are never modified, tagged, or moved on disk.
  • Timeline Export: Waveform trimming exports a temporary audio snippet into your OS temporary directory (%TEMP%); master source files remain completely untouched.

Network & Privacy Policies

  • Offline Operation: Searching, indexing, waveform rendering, and timeline drag-and-drop work entirely offline without an internet connection.
  • Zero Automatic Telemetry: Audio waveforms, file contents, and library data are never collected in the background or sent to external tracking servers.
  • Bug Reports & Debug Logs: If you manually submit a bug report through the application, generated debug logs may reference library paths or audio file names involved in the issue to help diagnose the problem.

Engineering Context

MySoundLib was designed and built independently by a video editor facing the daily friction of managing large audio libraries across tight deadlines. The architecture focuses strictly on lightweight desktop performance, low latency, and zero dependency on remote cloud infrastructure.
